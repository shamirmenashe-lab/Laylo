2Click track (reference)

Synthesized once, offline, so the exact reference sample array is known (x[n] for NLMS). Played back only through a plain <audio> element during recording — never through the WebAudio destination.

—
Alignment caveat (carried over): a fixed-interval periodic reference makes cross-correlation lag detection ambiguous at multiples of the interval (peaks are nearly equal). This harness restricts the lag search to ±50ms specifically to stay inside one period and avoid that ambiguity — it is not a fix for the periodicity itself, just a way to route around it. A misaligned-by-one-period lag is harmless for the dB math (signal is periodic), but don't trust the raw "Alignment lag" number as a literal latency measurement beyond that caveat.

3Recordings — Mode A (silent) vs Mode B (performance)

Each button gives you a 5-second countdown before the click track and recording actually start, so there's time to get ready. All three play the identical click track via <audio>; MediaRecorder captures the mic in parallel. No processing happens live — capture only. If you're only running the L×μ sweep (§5), you only need ① and ② — ③ (Overdub) is not required for that.

Mode B dB is not valid for L/μ comparison. Take ③ contains real performance energy on top of any bleed, so its residual level reflects the performance too, not just leftover bleed. Only Mode A (① vs ②) numbers are trustworthy for tuning — this was the exact bug found and fixed from v2. Mode B is used only to produce a cleaned file, never to judge filter quality.

4NLMS training + live diagnostics

All offline, after every MediaRecorder has fully stopped. Trains on ①, freezes, tests on ② (valid dB), applies to ③ (cleaned file, dB not valid).

Leak safety range: 0 = off (default). Safe tested range is 1e-7 to 1e-5. Do not use 1e-4 — confirmed destructive, accumulates to weight blowup over a ~240k-sample buffer (this was caught and fixed mid-session; the bug never shipped, but the number is dangerous enough to warn against explicitly in the UI).
Epochs re-passes the same calibration take through the filter multiple times (weights carry over) so a large L gets more update iterations to converge — without recording a longer take. This is the second, independent way (besides leak) to test whether L=4096 collapses from a real instability or just from not enough updates yet.

6Spectrum check — the cheap linearity/nonlinearity test

Runs on the ② validation residual from the last §4 run. Compares its spectrum against the reference click track's spectrum. If the residual has real energy at frequencies the reference doesn't contain at all, that's a direct nonlinearity signature (new harmonics / saturation) — no more L/μ runs needed to make that case. If the residual spectrum is just a quieter version of the reference's own frequencies, that points back to insufficient filter length, not nonlinearity.
